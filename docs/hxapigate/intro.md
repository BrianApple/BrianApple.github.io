# HXAPIGate（浩心 API 网关）产品介绍

## 项目简介

HXAPIGate（中文名：**浩心 API 网关**）是一款基于 **Netty + Shiro** 开发的高性能 API 网关，本质上是一个面向 REST 服务的**细粒度 API 资源权限管理平台**，同时支持 HTTP、Dubbo 等多协议微服务接口代理。

与多数仅对 API 路径本身授权的管理平台不同，HXAPIGate 通过组合 BootShiro（HXBootShiro 管理平台）实现了「**API 资源 + 请求方式**」的授权模式，可以在同一路径下按 GET / POST / DELETE / PUT 分别授权，做到真正的细粒度权限控制。

:::

## 核心特性

HXAPIGate 当前已实现的功能包括：

1. **授权、鉴权管理**：JWT 签名密钥支持通过环境变量外置注入，生产环境可安全托管密钥。
2. **路由配置**：支持熔断参数的 UI 可视化配置（失败阈值 / 成功阈值 / 超时毫秒）。
3. **路由负载**：支持轮询与赋权值（加权）等负载策略。
4. **多协议代理**：HTTP、Dubbo、MCP、WebSocket 四种协议代理，其中 WebSocket 支持双向透传、后端推送、断开传播与可配置空闲超时。
5. **接口分布式限流**：基于 Redis 计数信号量实现，支持集群环境下的分布式限流。
6. **金丝雀发布**：支持按版本与权重进行灰度发布。
7. **接口熔断**：状态机管理（Closed / Open / Half-Open），配置值优先于 TPS 自动推导值。
8. **管理平台首页统计**：ECharts 类型分布、接口状态图表。
9. **网关核心单元测试**：覆盖限流、负载均衡、熔断状态机（14 个用例全部通过）。

### 细粒度授权示例

假设后端新增如下四个接口：

| 接口路径 | 请求方式 |
|--|--|
| `/user/list` | GET |
| `/user/list` | POST |
| `/user/list` | DELETE |
| `/user/list` | PUT |

传统授权模式下，这四个接口因为路径一致会被当成**一个接口**整体授权给第三方；而通过 HXAPIGate 可以分别对每个资源授权——当仅授权 `/user/list` + `GET` 给第三方平台时，被授权方**无法访问**同一资源的 POST、DELETE、PUT 请求。

## 与同类方案的差异

### 为什么不选择 Spring Cloud

Spring Cloud 全家桶的学习成本较高，且要求业务服务全面改造。对于存在大量历史遗留系统、无法切换到 Spring Cloud 的公司，HXAPIGate 提供了一条低成本路径：**在不更改（或极少更改）业务代码的情况下**，为存量微服务赋予分布式限流、服务熔断等分布式特性。

### 为什么不选择 Dubbo

HXAPIGate 本身**兼容 Dubbo 协议**：用户侧统一为 HTTP 协议，网关虽然不对外提供 Dubbo 服务，但可以代理 Dubbo 微服务，同时也能实现对 Dubbo 接口的分布式限流。因此对于已经使用 Dubbo 的团队，HXAPIGate 可以作为流量入口的补充，而非替代。

### MECHA（机甲）思想

浩心网关是「微服务思想 + Mecha 思想」落地的产物：业务微服务区域不需要考虑任何分布式特性，也不需要引入与业务无关的第三方分布式组件；当一个业务微服务单元发布之后，浩心网关直接赋予该服务所有分布式特性。这与 Service Mesh 的思路神似，作者的目标之一是未来将 HXAPIGate 打造成工业级 Sidecar。

## 部署架构

HXAPIGate 支持**集群部署**，支持被代理接口的分布式限流、负载等能力：

- 分布式部署时，网关节点通过 **Redis** 进行分布式限流与配置同步；
- 管理平台（HXBootShiro）负责 API 路由与鉴权规则的统一管理；
- 项目已移除对 Ignite 的依赖。

网关启动后会自动从 Redis 拉取管理端下发的 API 路由与熔断 / 限流配置，因此管理端与网关之间通过 Redis 解耦。

## 项目状态与演进

- 管理平台前端已全面改造为 **Vue3 + Element Plus**（登录页粒子动画、API 两级类型、角色授权双栏等）。
- 技术栈升级为 **JDK 21 + Shiro 3.0 + jjwt 0.12**。
- 已完成一轮安全加固与质量优化：JWT 密钥与数据库口令环境变量化、死代码清理（−423 行）、网关核心单测补充（14 用例全通过）、API 熔断配置 UI 全链路打通、首页统计可视化升级。
- 后续规划：主要对 API 接口支持的代理协议以及网关 Bug 进行扩展和完善，同时扩展管理平台功能。
