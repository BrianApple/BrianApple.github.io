# 部署与运维

## 部署形态选择

IOTGate 网关与 IOTGateConsole 管理平台是两个独立工程，**二者可选搭配**：

| 形态 | 命令 | 适用场景 |
|------|------|---------|
| 仅网关（最小部署） | `-m` 直连前置 | 不需要管理平台，数据通道零依赖 |
| 网关 + 管理平台（推荐） | `-c -r <consoleIp>` | 需要节点监控、规约启停管理、AI 智能体等能力 |

使用前提：管理平台需配置 MySQL（本机 13306/3306 均可，见其 README）并启动；**网关侧无需任何配置依赖 Console 的注册表**——未启动 Console 时，网关仅以 `-m` 模式运行，不影响数据通道。

## 单机部署

```bash
java -jar iotGate.jar -n 1 -f /opt/iot/iotGate.conf -m 192.168.1.10
```

- `-n`：网关编号（必选）
- `-f`：`iotGate.conf` 本地全路径（必选）
- `-m`：前置 ip 地址，前置默认端口 8888

单机版可通过配置文件为每个规约个性化配置心跳周期（`iotGate.conf` 中的 `heartbeat` 字段）。

## 集群部署

自 v2.0 起集群模式**去除 Zookeeper 依赖**，通过 `-m` 直连前置（多个前置地址逗号分隔，数据通道零改动）；网关与前置通讯时默认采用**轮询方式负载均衡**：

```bash
java -jar iotGate.jar -n 1 -f /opt/iot/iotGate.conf -m 192.168.1.10,192.168.1.11
```

集群版心跳默认 **300 秒**。

## 与 IOTGateConsole 协同

集群模式下推荐使用 `-c -r` 开启"主动注册到前端管理服务"模式：

```bash
java -jar iotGate.jar -n 1 -f /opt/iot/iotGate.conf -c -r 192.168.1.100:8686 -m 192.168.1.10,192.168.1.11
```

- `-r`：IOTGateConsole 地址，支持 `ip` / `ip:port` / `http://ip:port`，默认端口 **8686**
- 注册成功后网关每 **10s** 向 Console 发送心跳；Console 侧 **30s** 未收到心跳自动判定节点离线并移除
- 网关正常关闭时主动**反注册**
- 心跳上报时若节点不存在，Console 返回 `retSig=404`，触发网关**自愈重注册**
- Console 侧注册表与静态 `gate.nodes` 配置**并存**：主动注册的节点优先，静态配置兜底

:::tip
部署多个网关节点时，`-n` 网关编号必须唯一，便于在 Console 节点管理页区分各节点。
:::

## 端口规划

| 端口 | 用途 | 说明 |
|------|------|------|
| 8888 | 前置(master)数据通道 | `-m` 参数直连 |
| 10915 | kernel 模式默认端口 | `-k` 参数开启 |
| 10916 | RPC 通信 | 集群模式下开启，Console 经此端口调用网关规约启停等 RPC |
| 9811/9812/9813… | 各规约终端接入端口 | 由 `iotGate.conf` 的 `port` 字段决定 |

生产环境请在防火墙中放行以上端口，并确保网关节点与 Console（8686）、前置（8888）之间的网络互通。

## 运维常用操作

### 查看运行状态

```bash
# 查看网关进程
ps -ef | grep iotGate

# 查看端口监听
ss -lntp | grep -E '8888|10916|9811'
```

### 日志与问题排查

- 终端无法接入：检查对应规约端口是否监听、`iotGate.conf` 中 `port` 字段是否冲突
- 数据无法转发：检查前置地址与 8888 端口连通性、网关头登录报文是否正确（登录时 `type=03`、`protocolType=15`、`count=1`）
- 拆包异常：核对长度域参数（偏移、长度、是否含长度域、额外长度）与协议文档是否一致

## 常见问题（FAQ）

### Console 未启动时网关还能运行吗？

可以。网关侧不依赖 Console 的注册表，未启动 Console 时网关仅以 `-m` 模式运行，不影响数据通道。

### 静态配置节点为什么一直显示离线？

Console 节点列表中的在线状态由定时 TCP 探测得出（每 10s 探测一次节点的 10916 RPC 端口）。静态配置不存在的 IP 会一直显示离线；静态配置本机 `127.0.0.1` 且网关运行中则显示在线。请确认 `gate.nodes` 中配置的 IP 与网关实际 IP 一致。

### 动态注册节点掉线后会自动恢复吗？

网关注册成功后每 10s 发送心跳，Console 30s 未收到心跳判定离线；若节点被移除，网关下次心跳会收到 `retSig=404` 并自动重新注册，实现自愈。

### 修改规约配置需要重启网关吗？

本地 `iotGate.conf` 方式需要重启网关生效；通过 IOTGateConsole 在线新增/删除/启停规约则实时同步到网关，无需重启。
