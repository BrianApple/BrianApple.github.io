# AI 智能体（v3.0.1）

IOTGate v3.0.1 为 **AI 智能体版本**，内置 LangChain4j AI 智能体，与 IOTGateConsole 智能体控制台配套。控制台内置 🤖 悬浮智能体机器人（右下角，主流客服交互设计），集**对话解析**、**一键创建规约**与**大模型配置管理**于一体。

## 能力总览

| 能力 | 说明 |
|---|---|
| **帧结构解析** | 粘贴协议帧结构描述 → 推导拆包/黏包解码参数 → 一键填充表单 |
| **初/高级自动判断** | 自动识别该协议用基础规约还是**高级规约**（自定义长度域解析），高级规约可直接一键创建 |
| **流式输出 + 思考过程** | 思考与正文分段流式返回，思考区可折叠/自动展开/自动收起；支持**停止**中断 |
| **多轮对话** | 同一会话内可连续补充信息（自动去重、上限 12 条），逐步逼近正确参数 |
| **多模型配置** | `ai_config` 支持配置多个模型，对话面板可随时切换（选择记忆在本地） |
| **对话记录落库** | 每轮问答（含思考过程）落库 `ai_chat_message`，可按会话查询历史 |
| **缺参追问** | 决定性参数缺失时主动追问；非决定性参数（端口/心跳等）用默认值并告知 |

## 对话解析与一键创建

粘贴通信协议的**帧结构描述**（协议文档中的字段定义：帧头、各字段字节数、**长度域位置与定义**、字节序、校验帧尾等），AI 自动提取长度域信息并推导解码参数：

![AI 智能体对话解析（流式思考过程 + 结构化结果）](/img/iotgate/bot-chat-v3.0.2.png)

### 操作步骤

1. 进入控制台任意页面，点击**右下角 🤖 悬浮机器人**（图标可拖拽，拖到顺手的位置不会误触发开关）
2. 在面板顶部**模型下拉**中选择使用的模型（选择会被记住）
3. 把协议文档里的**帧结构描述**粘贴到输入框——可以直接粘原文片段（含章节编号、图表说明、位定义），不必整理成规范清单
4. 点「发送」；此时按钮变为红色「**停止**」，需要中断就点它（后端会同时断开与模型的连接，停止生成）
5. **思考区**会流式输出推理过程（自动展开、自动滚动；正文开始后自动收起），点标题可手动折叠/展开
6. 收到结构化结果后：
   - 判定为**基础规约** → 点「一键填充」，参数进入新增规约表单，确认后保存
   - 判定为**高级规约** → 直接一键创建（含长度域解析实现）
7. 若 AI 有**待追问项**，用追问框逐条补充回答；缺少规约名称/编号时会弹框要求填写
8. 保存/创建后规约变更**实时同步到网关**

### 推导的解码参数

| 参数 | 说明 |
|---|---|
| `pName` | 规约名称（根据上下文合理命名） |
| `isBigEndian` | 长度域字节序：`1` = 大端，`0` = 小端 |
| `beginHexVal` | 起始字符十六进制，无起始符为 `-1` |
| `lengthFieldOffset` | 长度域起始位置相对报文头的偏移字节数 |
| `lengthFieldLength` | 长度域占用的字节数（`1`/`2`/`4`） |
| `isDataLenthIncludeLenthFieldLenth` | 长度值是否包含长度域自身字节数：`1` = 包含，`0` = 不包含 |
| `exceptDataLenth` | 长度值之外需额外加减的字节数（如 CRC / 帧尾） |
| `port` | 建议的监听端口 |
| `heartbeat` | 心跳周期（秒），描述未给出默认 300 |

参数语义详见 [iotGate.conf 参数详解](./reference/iotgate-conf.md)。

### 基础 / 高级规约自动判断

AI **默认判为基础规约**；仅当描述中出现「低位另有含义 / 需要拼装 / 需要按位提取」这类特征时，才判为**高级规约**并给出长度域解析代码：

| 判定结果 | `type` | 前端行为 |
|---|---|---|
| 基础规约 | `0` | 回落**填充新增规约表单**，由用户确认后保存 |
| 高级规约 | `1` | 携带 `content`（长度域解析代码）**直接调用高级规约创建接口**一键创建 |

返回值中的 `questions` 为**待追问项**：当**决定性参数**（如长度域位置、字节序）缺失时进入追问；**非决定性参数**（端口、心跳等）则填入 `defaults` 使用默认值，并在结果中告知用户。

取值优先级：**用户补充 ＞ 描述原文 ＞ 默认值**。

:::warning 规约名称与编号需确认
若描述中缺少规约名称或 `pId`，前端会**弹框让用户填写**——因为 IOTGate **不支持编辑规约**（网关侧只有 `ADD_PROTOCOL` / `DELETE_PROTOCOL`），建错只能删除后重建。
:::

### 使用流程

1. 在 IOTGateConsole 页面右下角呼出悬浮机器人（图标可拖拽）
2. 将协议文档中的帧结构描述粘贴到对话框
3. AI 流式返回**思考过程**（可折叠）与**结构化结果**
4. 若被判为高级规约 → 一键创建；若为基础规约 → 参数自动填入新增规约表单，确认后保存
5. 缺少规约名称 / `pId` 时按弹框补齐后创建
6. 保存/创建后规约变更**实时同步到网关**

## 流式输出与思考过程

解析接口提供**流式**版本，思考过程与正文分段推送：

- 端点为 `POST /rpc/ai/parse/stream`，通过 SSE 推送事件：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `thinking` | `{"d":"思考增量"}` | 大模型思考过程（reasoning），逐段推送 |
| `phase` | `{"phase":"content"}` | 正文开始输出（前端据此自动收起思考区） |
| `result` | `{"retSig":200,"data":{…}}` | 解析完成的最终结构化结果（与阻塞版同构） |
| `error` | `{"retSig":500,"error":"…"}` | 失败（前端据此回退到阻塞接口） |

**思考过程的兼容处理**：自研流式客户端同时兼容三种返回形式，避免思考被丢弃：

1. `delta.reasoning`（Ollama 系）
2. `delta.reasoning_content`（DeepSeek 系）
3. 正文中**内联 `thinking` 标签**（由内置切分器拆分）

**可中断**：前端点击**停止**（解析中「发送」按钮变为红色「停止」）或断开连接，后端即停止读取并断开与模型服务的连接，使模型停止生成。原**阻塞接口保留**作为回退。

## 多轮对话

同一会话内可连续补充信息，逐步修正参数：

- 前端维护 `sessionFrameDesc`（原始描述）+ `sessionContext`（累积补充），每轮把补充信息作为**最高优先级段**拼入提示词
- 补充信息**自动去重**且**上限 12 条**，避免多轮累积膨胀或矛盾堆叠

## 多模型配置

`ai_config` 支持**多行配置**（新增 `name` 列，原单行成为「默认」）。对话面板头部提供**模型下拉**，选择结果记忆在本地，每条请求携带对应模型；设置面板改为**模型列表管理**，API Key **脱敏回显**：

![大模型配置面板](/img/iotgate/bot-settings-v3.0.2.png)

**厂商无关**设计，支持任意 OpenAI 兼容接口（DeepSeek / 通义千问 / 智谱 GLM / Ollama / OpenAI 等）。可视化修改模型地址、模型名称、API Key、采样温度、超时时间，**保存立即生效，无需重启**。

### 默认配置

默认配置位于 `application.properties`，运行时可在前端设置中覆盖：

```properties
ai.api-key=${DEEPSEEK_API_KEY:}    # 建议环境变量注入，勿硬编码提交
ai.base-url=https://api.deepseek.com/v1
ai.model=deepseek-chat
ai.temperature=0.1
ai.timeout-seconds=300
```

### 常见模型切换示例

| 模型 | base-url | model |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4` |
| Ollama 本地 | `http://localhost:11434/v1` | 本地模型名（无需 Key） |

:::tip base-url 填根地址即可
填成完整端点（如粘上 `/chat/completions`）时，后端会自动剥离多余路径段，无需手工裁剪。
:::

## 对话记录落库

解析完成后自动落库到 `ai_chat_message` 表，字段包含：`sessionId` / `role` / `content` / `thinking` / `modelId` / `modelName` / `createTime`。

- 流式解析会**连同思考过程一起存**
- 落库为**容错设计**：写库失败不影响对话本身
- 前端「清空」即切换到新会话

## API 一览

| 接口 | 说明 |
|---|---|
| `POST /rpc/ai/parse` | 解析帧结构描述（阻塞版，返回拆包/黏包解码参数） |
| `POST /rpc/ai/parse/stream` | **流式**解析（SSE：`thinking` / `phase` / `result` / `error`） |
| `GET /rpc/ai/models` | 模型列表 |
| `POST /rpc/ai/models` | 新增模型 |
| `POST /rpc/ai/models/update` | 修改模型 |
| `POST /rpc/ai/models/delete` | 删除模型 |
| `GET /rpc/ai/config` | 获取大模型配置（兼容旧接口，API Key 脱敏） |
| `POST /rpc/ai/config` | 动态更新大模型配置（兼容旧接口，即时生效） |
| `GET /rpc/ai/chat/sessions` | 会话列表 |
| `GET /rpc/ai/chat/messages?sessionId=` | 某会话的对话记录 |

## 技术栈

- **LangChain4j 1.18**：AiServices 声明式结构化输出
- 控制台为 **JDK 21 + Spring Boot 3.5**
- 前端为 Vue3 + Vite 单页应用；悬浮机器人图标使用 SVG 矢量图（避免无 emoji 字体环境下显示为 ×）

## 使用前提与注意事项

- **配套版本**：AI 智能体能力由 IOTGateConsole 提供，请使用 **v3.0.1 及以上**版本的控制台与网关配套部署
- **模型可用性**：请确保大模型已正确配置（模型地址、模型名称、API Key），否则 AI 解析功能不可用；Ollama 本地模型无需 Key
- **思考过程显示**：需要所选模型**支持 reasoning 输出**（如 DeepSeek 推理模型、Ollama 推理模型）才会推送 `thinking` 事件
- **配置持久化**：模型配置保存后持久化，重启后保留；前端设置中的修改会覆盖 `application.properties` 默认值
- **Key 安全**：API Key 建议通过环境变量 `DEEPSEEK_API_KEY` 注入，避免明文口令入库，勿硬编码提交

## v3.x 展望
