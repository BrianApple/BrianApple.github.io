# 架构与核心概念

## 整体架构

IOTGate 网关与前置（master）服务、IOTGateConsole 管理平台组成典型的"终端 → 网关 → 前置"三级结构：

- **感知终端**：通过 TCP 长连接接入网关，按各自规约（应用层协议）发送真实报文
- **IOTGate 网关**：负责终端连接的接入管理、多规约报文的拆包/黏包解析，并将真实报文按自定义网关头封装后转发给前置
- **前置（master）**：接收网关转发的数据，默认数据通道端口 **8888**；多个前置可组成集群，网关与前置通讯时默认采用**轮询方式负载均衡**
- **IOTGateConsole（可选）**：Web 管理平台，通过 RPC（网关 10916 端口）远程管理网关的规约启停与策略配置

入口类为 `Entrance.java`，通过命令行参数（`-n` / `-c` / `-r` / `-m` / `-k` / `-f`）决定网关的运行模式。

:::note
自 v2.0 起架构发生重要演进：**去除 Zookeeper 依赖**，集群模式改为 `-m` 直连前置（多个前置地址逗号分隔，数据通道零改动）；新增 `-c -r` 网关主动注册模式（HTTP 注册 + 10s 心跳 + 404 自愈重注册），与 IOTGateConsole v2.2 智能体版配套形成完整部署形态。
:::

## Netty 高并发模型

IOTGate 基于 Netty 实现自定义协议的 TCP 长连接服务，具备以下高并发特性：

- **长连接保持**：终端与网关建立连接后保持在线，支撑大规模在线终端
- **自定义编解码**：Netty 的 handler 链完成报文的解码与编码，长度域驱动拆包/黏包处理
- **心跳机制**：单机版可在 `iotGate.conf` 中为每个规约个性化配置心跳周期；集群版默认心跳 **300 秒**

官方压测数据（Windows 笔记本、堆内存 2G、线程数 6K）：

- 单网关、单前置节点，每秒处理并发心跳 **8000+**
- **20 万**在线终端（长连接保持）时内存占用约 **1G**

## 多规约解析机制

网关通过配置文件 `iotGate.conf` 以"**一条规则 = 一个规约**"的方式管理多套解析参数，规则之间分号分隔，每条规则包含：

```properties
pId, isBigEndian, beginHexVal, lengthFieldOffset, lengthFieldLength, isDataLenthIncludeLenthFieldLenth, exceptDataLenth, port, heartbeat
```

网关启动时通过 `-f` 加载该文件（必选参数），每个规约绑定一个独立的监听端口，互不干扰。这些参数本质上是 Netty 拆包/黏包解码（长度域解码）的配置项：通过**长度域偏移**与**长度域长度**定位长度字段，再结合**长度是否包含长度域本身**与**额外长度**计算出完整报文长度，从而正确切分数据帧。

:::warning
长度域相关参数一旦配置错误，网关将无法正确拆包，终端与前置之间的数据链路会直接异常。建议接入新规约前先仔细阅读协议文档中的帧结构定义。
:::

## 网关核心模块

### 终端接入（真实报文解析）

终端与网关通信时传输的报文称为"真实报文"，规约不同则报文结构差异明显。配置文件默认支持两种真实报文结构：

**规约编号为 1 的报文结构：**

| 报文属性 | 字节数 | 含义 |
|---------|-------|------|
| `68` | 1 byte | 报头 |
| `len` | 2 byte | 长度域：传输帧中除起始字符 68 和结束字符 16 之外的帧字节总数，包含长度域本身字节数 |
| `data` | n byte | 报文内容 |
| `16` | 1 byte | 报尾 |

**规约编号为 2 的报文结构：**

| 报文属性 | 字节数 | 含义 |
|---------|-------|------|
| `len` | 4 byte | 长度域：值为 data 的字节数，不包含自身字节数 |
| `data` | n byte | 报文内容 |

### 前置通信（自定义网关头）

网关与前置通信时，会在真实报文前封装自定义的**网关头**，用于网关登录和携带网关自身与终端响应参数。网关头报文结构如下：

| 报文属性 | 字节数 | 含义 |
|---------|-------|------|
| `AB` | 1 byte | 报文头 |
| `len` | 4 byte | 长度域：真实报文长度，包含"68"、"16" |
| `type` | 1 byte | 报头类型 |
| `protocolType` | 1 byte | 协议类型（左侧起第一个 bit 为 0 表示 IPV4，1 表示 IPV6；剩余 7 个 bit 表示规约类型编号） |
| `gateNum` | 1 byte | 网关编号 |
| `00*12` | 12 byte | 若 ip 格式为 IPV4，则为 12 字节 0；反之当前 12 字节 + 后续 4 字节存放 IPV6 的值，存放顺序从左至右 |
| `clientIP` | 4 byte | 终端的 IP 地址，ip 地址的每个段位占一个字节（不含符号和端口号） |
| `port` | 2 byte | 终端对应的端口号 |
| `count` | 4 byte | 终端与网关建立连接时对应的连接序号（1-10000 循环） |

网关启动时会向前置发送**登录报文**完成注册，规则如下：

1. 登录时长度域为 0；有真实报文时，长度域为整个真实报文长度值
2. 登录时 `type = 03`、`protocolType = 15`、`count = 1` 都为固定值；发送真实报文时 `type = 01`、`protocolType = 00`、`count = 终端与网关的连接序号`
3. 前置发现报头长度为 0 且 `type = 03`、`protocolType = 15` 时，不会执行解析数据的方法；否则继续解析真实报文

### kernel 服务模式

除常规的 normal 部署模式外，IOTGate 还支持与 master 节点通信的 **kernel 模式**（`-k` 命令行参数开启，默认端口 **10915**）。在该模式下，master 节点和所有的感知终端统一作为与 IOTGate 服务网络通信的客户端服务，适合将网关作为网络中心节点的部署场景。

## 端口规划

| 端口 | 用途 |
|------|------|
| 8888 | 前置(master)数据通道（`-m` 参数直连） |
| 10915 | kernel 模式默认端口（`-k` 参数开启） |
| 10916 | RPC 通信（集群模式下开启，Console 经此端口调用网关规约启停等 RPC） |
| 9811 / 9812 / 9813… | 各规约对应的终端接入端口（由 `iotGate.conf` 的 `port` 字段决定） |
