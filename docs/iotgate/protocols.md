# 规约接入

## 什么是通信规约

在 IOTGate 中，"通信规约"指**应用层通信协议**（与一些同学说的"通信协议"是一个意思），即终端设备与网关之间传输数据的报文格式约定。规约不同，报文结构差异明显，因此网关需要为每种规约配置独立的解析参数。

## 规约配置方式

IOTGate 支持两种规约管理方式：

1. **本地配置文件**：通过 `-f` 参数加载 `iotGate.conf`，在文件中配置多套规约规则（离线静态配置）
2. **远程管理（推荐）**：配合 IOTGateConsole，在线开启/关闭/新增/删除多规约解析服务，变更实时同步到网关

## 配置文件格式

配置文件 `iotGate.conf` 中，多个规则之间用**分号**分隔，每个规则为一条记录：

```properties
# pId,isBigEndian(0=false),beginHexVal,lengthFieldOffset,lengthFieldLength,isDataLenthIncludeLenthFieldLenth(0=false),exceptDataLenth,port,heartbeat
protocolType=1,0,-1,1,2,1,1,9811,60;2,1,-1,0,4,0,0,9812,300;3,1,-1,4,2,0,0,9813,130;
```

### 字段详解

| 字段 | 说明 |
|------|------|
| `pId` | 规约编号，`pId=1` 为默认规约 |
| `isBigEndian` | 是否大端字节序，`0` 表示 false（小端），`1` 表示 true（大端） |
| `beginHexVal` | 起始符（十六进制值），`-1` 表示无起始符 |
| `lengthFieldOffset` | 长度域在帧中的偏移量 |
| `lengthFieldLength` | 长度域占用的字节数 |
| `isDataLenthIncludeLenthFieldLenth` | 数据长度是否包含长度域本身，`0` 表示 false |
| `exceptDataLenth` | 额外长度（长度域计算出的长度之外需要补充/扣减的字节数） |
| `port` | 该规约对应的终端接入端口号（废弃原 `-p` 命令行参数指定启动端口的方式） |
| `heartbeat` | 该规约的心跳周期（秒） |

:::tip
这些参数对应 Netty 长度域解码（拆包/黏包）的核心配置：先按 `lengthFieldOffset` 定位长度域，按 `lengthFieldLength` 读取长度值，再结合"长度是否包含长度域"与"额外长度"计算出完整数据帧长度。
:::

## 常见规约配置示例

README 中给出了以下三种常见规约的配置信息：

### modbus TCP

```properties
1,1,-1,4,2,0,0,9813,60
```

- 规约编号 1、大端、无起始符、长度域偏移 4、长度域 2 字节、长度不含长度域、无额外长度、端口 9813、心跳 60 秒

### IEC 104

```properties
2,1,-1,1,1,0,0,9814,60
```

- 规约编号 2、大端、无起始符、长度域偏移 1、长度域 1 字节、长度不含长度域、无额外长度、端口 9814、心跳 60 秒

### DLT 645

```properties
3,0,-1,9,1,0,2,9815,60
```

- 规约编号 3、小端、无起始符、长度域偏移 9、长度域 1 字节、长度不含长度域、额外长度 2、端口 9815、心跳 60 秒

:::note
上述示例中的 `pId` 为 README 文档中的演示编号，实际部署时请以 `iotGate.conf` 为准（仓库默认配置中 `pId=1` 为默认规约）。
:::

## 接入新规约的步骤

1. **阅读协议文档**：确认帧结构中的起始符、长度域位置与长度、字节序（大小端）、帧尾等字段定义
2. **编写配置**：按 `pId,isBigEndian,beginHexVal,lengthFieldOffset,lengthFieldLength,isDataLenthIncludeLenthFieldLenth,exceptDataLenth,port,heartbeat` 格式追加一条规则（分号分隔）
3. **重启网关**：通过 `-f` 指定配置文件路径启动，或使用 IOTGateConsole 在线新增规约（无需重启，变更实时同步）
4. **验证报文**：使用终端模拟器连接该规约对应的端口，确认拆包/转发正常

## 使用 AI 智能体辅助配置（v2.2）

如果觉得手工推导长度域参数比较繁琐，可以配合 IOTGateConsole v2.2 的悬浮智能体机器人：

1. 将协议文档中的**帧结构描述**（帧头、各字段字节数、长度域位置与定义、字节序、校验帧尾等）直接粘贴给机器人
2. 大模型自动提取长度域信息，推导拆包/黏包解码参数（大小端 / 起始符 / 长度域偏移 / 长度域长度 / 长度含长度域标志 / 额外长度 / 端口）
3. 在规约表单中**一键填充**，保存后即完成新规约接入

:::warning
AI 推导结果仍建议对照协议文档人工复核一遍，特别是长度域偏移、长度域长度这类直接影响拆包正确性的参数。
:::

## 注意事项

- 网关报头（网关头）是网关与前置通信时使用的固定封装格式，与终端侧的规约报文无关，接入新规约时不需要修改网关头
- 每个规约绑定独立端口，端口冲突会导致网关启动失败
- 单机版可通过配置文件为每个规约**个性化配置心跳周期**（`heartbeat` 字段），使不同规约的心跳管理更加灵活；集群版默认心跳 300 秒
